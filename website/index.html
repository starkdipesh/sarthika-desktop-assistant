Here is an in-place quicksort implementation with an explanation of partitioning:

def quicksort(arr, low=0, high=None):
    if high is None:
        high = len(arr) - 1
    if low < high:
        pi = partition(arr, low, high)
        quicksort(arr, low, pi - 1)
        quicksort(arr, pi + 1, high)
    return arr

Why Local-First?

Your source code represents proprietary intellectual property and personal engineering craft. It should never be broadcast to third-party cloud servers.

🔒

Zero Cloud Inference

Model inference runs entirely on your CPU via local loopback (127.0.0.1). No source code, context files, or prompts ever touch remote infrastructure.

🚫

Zero Telemetry & Accounts

No account sign-ups, no subscriptions, no tracking beacons, no analytics collectors, and no advertising networks. It operates completely offline.

💻

Designed for Ordinary Laptops

Optimized for efficient 4-bit quantized models that execute cleanly on multi-core consumer x86_64 CPUs without requiring an expensive NVIDIA GPU.

🛡️

Non-Destructive & Safe

Never executes terminal commands, never executes generated code, never edits your project files silently, and never runs automated Git operations.

Features Designed for Developers

You choose exactly which files to attach as context. The built-in security scanner automatically blocks sensitive secrets, .env files, private SSH keys, and bloated directories (node_modules).

Token Budgeting & Capacity Gauges

Real-time context budgeting estimates prompt and context tokens before generation, warning you if file attachments approach model context limits.

Persistent Local Conversations

All chats, messages, and settings are stored in local SQLite databases on your machine. Export conversations anytime as clean Markdown or Plaintext files.

Offline Mock & Demo Mode

Explore the entire desktop application, editor, syntax highlighter, and workflow cards offline without needing to download model weights first.

System Diagnostics & Safe Logs

Inspect CPU, RAM, process uptime, and generation metrics with a single click. Diagnostic reports automatically redact user home directory paths for private sharing.

Model & Engine Setup

Download your model weights directly from verified open-source sources.

Recommended Model

Qwen2.5-Coder 3B Instruct

A compact, highly capable open weights model specifically fine-tuned for code explanation, refactoring, and unit test generation.

  • Quantization: Q4_K_M (4-bit Medium)
  • File Size: ~1.9 GB
  • Format: Standard .gguf
  • License: Apache 2.0 (by Qwen Team)
Inference Engine

llama.cpp (llama-server)

The standard C++ inference engine for local LLMs, maintained by Georgi Gerganov and the open-source community.

  • Windows Binary: llama-server.exe
  • Connection: Local loopback (http://127.0.0.1:8080)
  • Source: Official llama.cpp GitHub Releases
  • License: MIT License

Privacy & Security Guarantees

Architectural commitments you can audit in the source code.

No Cloud Egress

Network sockets are strictly bound to 127.0.0.1. The application cannot transmit data to external IP addresses or domains.

No Silent Modifying

Sarthika Code never modifies your source files, never creates commits, and never alters project structures. Generated code is output in the chat for your review.

Sensitive-File Scanner

Files matching patterns like .env*, id_rsa, *.pem, *.key, or directory names like node_modules are blocked from entering prompt context.

Local Data Ownership

Conversations and settings reside in a local SQLite file in your user profile. You can delete individual chats or purge all records at any time.

Honest Product Limitations

What Version 0.1 cannot do and where human review is essential.

  • Not AGI or Autonomous: Sarthika Code does not possess human-level intelligence or full autonomy. It is an assistive tool to accelerate coding tasks.
  • Output Requires Human Review: Model responses can be incorrect, out of date, or produce invalid syntax. Always test and verify generated code.
  • No Terminal or Tool Execution: Version 0.1 does not execute shell scripts, run compilers, execute tests, or install packages.
  • No Web Browsing or Live APIs: The model cannot browse the internet or access external documentation APIs.
  • Context Window Limits: 3B models running on laptops are bounded by 2048 to 4096 tokens. Large multi-file repositories cannot be ingested in a single turn.

Transparent Benchmark Methodology

Measure real performance on your exact CPU using open benchmark tooling.

Sarthika Code includes a reproducible benchmark harness (scripts/benchmark_local.py) featuring 50 standardized engineering tasks across 5 categories: Laravel tasks, Python tasks, debugging cases, code explanations, and implementation planning.

To run benchmarks locally on your computer:

# Run local benchmark against your running llama-server:
python scripts/benchmark_local.py --server-url http://127.0.0.1:8080

# Or run with the offline mock provider:
python scripts/benchmark_local.py --mock

Results are saved strictly on your local disk in benchmarks/ as structured JSON. No data is sent to external servers.

Installation & Getting Started

Get up and running on Windows or set up from source on Linux.

Windows Standalone Release (Recommended)

  1. Download the latest release: SarthikaCode-0.1.0-win64.zip.
  2. Extract to C:\Users\<YourUser>\AppData\Local\Programs\SarthikaCode\.
  3. Double-click SarthikaCode.exe to launch.
  4. Configure your local llama-server.exe and .gguf model file in the setup screen.
Python is not required for packaged Windows end users.

Developer Setup (Linux & Source)

git clone https://github.com/your-username/sarthika-code.git
cd sarthika-code
python3.11 -m venv .venv
source .venv/bin/activate  # On Windows: .venv\Scripts\Activate.ps1
pip install -e ".[dev]"
python run.py
Pre-packaged Linux desktop packages (AppImage/deb) are planned for future releases.
